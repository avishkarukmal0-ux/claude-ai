## Approach
A UX/UI/CX improvement request over an app that has already had 5 audit rounds + a feature-polish pass. I
inspected the owner journey end-to-end (first visit → NichePicker/sample mode → account → Today "Do this
today" → Scan/Stock/Buy hubs → More → help/recovery/billing) before changing anything, and found the shell is
already mature: one card/Row/Hub/Chip/NavTab system, per-screen ErrorBoundary, honest save/sync/offline
status, role gating + feature flags, and a real accessibility layer in `index.css`
(`prefers-reduced-motion`, `:focus-visible` rings, a WCAG-AA contrast lift for `text-gray-400`, a skip link).
So this pass fixed genuine defects rather than restyling working screens (claims kept proportional to evidence).

## Changes
1. **Home "Do this today" list key** — `TodayActions` mapped each `<li>` with **no `key`**, triggering React's
   list-key warning and risking mis-reconciliation when a row is snoozed (the home screen's most-used list).
   Added `key={a.id}`. Regression test seeds a past-use-by "pull" + a low-stock "low" action and asserts the
   list renders with no key warning.
2. **Credit-note repair clarity** (`CreditNoteRecoveryView`, explicitly "improve and test it") — each mismatched
   row now states the exact outcome before the owner taps ("Reconcile will set this claim to £X" / "…remove the
   £Y credit"), and the match indicator no longer relies on colour alone ("(differs)" text + `aria-label`s).
   Test asserts the outcome hint shows. The verify-before-clear recovery guarantee is unchanged.
